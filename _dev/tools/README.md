# 夜間テスト用の道具（preview/index.html 用）

作業用フォルダ（例：scratchpad/t）にコピーして、そのフォルダで実行する。

1. `node ext.js` … preview/index.html から DAW編の中身（DAW_HTML）を取り出して daw.html を作る
2. テスト用に内部をさわれるようにする：
   `python3 -c "s=open('daw.html',encoding='utf8').read();s=s.replace('function showStep(){','window.__g=function(c){return eval(c)};function showStep(){',1);open('dawt2.html','w',encoding='utf8').write(s)"`
3. `node walk.js D-1,D-2 [幅] [高さ] [t=タッチ]` … 実際のマウス操作（手のヒントの位置をクリック等）でレッスンを進める。
   - `NOT CONFIRMED` … その操作で進めなかった（自由入力のステップなど、道具が対応していないものもある）
   - `COVERED` … ハイライト対象の中心が吹き出しに隠れている
   - `finish=true` … クリア画面まで到達
   - スクショ shot_<ID>_<ステップ>.png を出力
4. `node page.js` … preview/index.html 全体を開いてページエラーを確認（Supabase等の通信は遮断）
5. `node chord.js [幅] [高さ] [t]` … D-17/D-18 のコードボタン操作を実操作で確認
6. `node mixwalk.js D-26,D-27 [幅] [高さ] [t]` … ミキサー系レッスン（D-26〜D-34）をフェーダー・パン・M/S・EQ等の実操作で進める。`COACH over` ＝操作する場所が吹き出しに隠れている、`needed-scroll` ＝自分でスクロールしないと見えない
7. `node d23.js [幅] [高さ] [t]` … D-23（消しゴムでクリップを消す）を実操作で確認。ok:false ＝そのクリップが画面に見えていない
8. `node walk3.js D-11,D-13 [幅] [高さ] [t]` … walk.js の改良版。手のヒントが「消す→置く」と順に変わるステップ（gs:'pts' / 'dblP'）を、ヒントが消えるまで追いかけてクリックする
9. `node kwalk.js all|1-1,2-3 [幅] [高さ] [t]` … 基礎編の汎用テスト（index.html から開く）。各ステップで押せる部品を実クリックして「つぎへ」が有効になるか、部品が親画面やレッスン内の何かに隠れていないか、24px未満の小さい部品を記録。決まった置き方が必要なステップは「汎用クリックでは進めず」と出る（不具合ではない）。1回20分以上かかる
10. `node rpov.js` … 各画面（ホーム・基礎レッスン・DAWマップ・リズム・ショートカット・用語辞典・その他・スタジオ）× 6つの画面サイズで、「ほうこく」ボタンの下に操作部品が隠れていないか
11. `node rh.js [幅] [高さ] [t]` … リズム編の全ステージで、パッドやボタンが親画面の部品に隠れていないか
12. `node exk.js` … preview/index.html から基礎編の各レッスンの中身を L_<ID>.html に取り出す（コードを読む用）
13. `node ksolve.js 2-4,3-6 [幅] [高さ] [t]` … 基礎編の「決まった置き方」が必要なステップを、①ヒントボタン→光ったマスを実クリック、②だめなら実クリックの探索（ランダム）で進めるか。`OK(ヒント)` ＝ヒントどおりで進めた。「進めず」はランダム探索の限界のこともあるので、tslot.js 等で個別確認する。時間がかかるのでバックグラウンド実行推奨
14. `node tslot.js [幅] [高さ] [t] [b]` … 4-3〜4-5（b を付けると 5-2〜6-4）の正しい答えを「パレット→四角」の実クリックで置いて ▶ で進めるか
15. `node h27.js [幅] [高さ] [t]` … 2-7「お手本を聴いて同じリズム」でヒントを押し続けると置く場所が光り、そのとおりに置くと進めるか
16. `node t37.js [幅] [高さ] [t]` … 3-7 の4つのチェック（音6つ以上・さいごがド・くりかえし・▶）を実クリックでそろえて進めるか
17. `node dawmenu.js [幅] [高さ]` … DAW編の上のメニュー（ファイル／編集…）と右クリックメニューのキーボード操作（Tabで到達・Enter/↓で開く・↑↓Home/Endで移動・←→でとなりのメニュー・Esc/Tabで閉じて元へ・Spaceは再生のまま）
18. `node knext.js [1-1,2-1,...]` … 基礎編でキーボードだけで「つぎへ」を押したとき、ステップが変わってもフォーカスが消えないか（BODY に落ちたら lost）。後半はマウスで押したときに枠が出ないか
19. `node ktab.js [1-1,2-3,...]` … 基礎編レッスンの Tab の順番と、キーボードで押せない「押せる見た目の部品」が無いか
20. `node menutap.js` … スマホ横（タッチ）で DAW編の上のメニューをタップして開き、項目をタップして閉じるか
21. `node dawcoach.js` / `node dawcoach_m.js` … DAW編の吹き出し：キーボードで操作しているときは「つぎへ」にフォーカスが置かれ Enter で進めるか（dawcoach）、マウスのときはフォーカスを動かさず枠も出ないか（dawcoach_m）
22. `node dawqz.js` … DAW編の上の「クオンタイズ／タイムベース／スナップ」をキーボードで開いて選べるか
23. `node dawmap.js` … DAW編で、押せる見た目なのにキーボードで届かない部品（nf）と名前のない部品
24. `node rhkey.js` … リズム編のマップとステージの Tab 順、キーボードで届かない部品
25. `node dawrt.js [幅] [高さ]` … DAW編「自由につくる」の往復テスト。**DAWを変えたら必ず回す。**作業フォルダで実行する（http://localhost:8765/ でリポジトリを配信しておく：リポジトリ直下で `python3 -m http.server 8765`）。
   - 4小節の曲（ドラム・ベース・メロディ・コード C→G→Am→F）を作る
   - 実際のマウス操作で確認：鉛筆クリックで置く／鉛筆でなぞると長い音／消しゴムクリックで消す／矢印1回では増えない／矢印ダブルクリックで置く
   - MIDI書き出し → `mid.py` で読んで、テンポ・トラック名・チャンネル・全部の音（開始・高さ・長さ）が曲と一致するか
   - プロジェクト保存 → 読み込み直して全部一致するか
   - ページエラー0件。最後に「結果：すべてOK」か「NG あり」。out.mid・proj.json・dawrt.png を作業フォルダに出す
26. `python3 mid.py ファイル.mid` … MIDIファイルの中身（テンポ・トラック名・音・終了がない音などの異常）をJSONで出す。ほかのDAWで開く前の確認用
27. `node dawfree.js [幅] [高さ] [t=タッチ]` … DAW編「自由につくる」で、4小節の曲をマウス（タッチ）とキーボードだけで作る通しテスト（4小節チャレンジ用）。マップ→スタジオ → ＋でドラム → 鉛筆で4小節のクリップ → ダブルクリックで開いてドラムを置く（もう一度押すと消える・横スクロールして2小節め）→ 楽器ブラウザからピアノを追加（せまい画面ではフォルダのボタンで開く）→ メロディを置く → Ctrl+Z／Ctrl+Y（打ち込み画面は開いたまま）→ Ctrl+D 複製・Delete → テンポ → ▶■ → マップに戻ってもう一度開くと曲が残っているか → 学習記録に保存されるか。おすすめ：`1366 768`、`1024 600`、`844 390 t`
28. `node dawplay.js` … DAW編「自由につくる」の再生テスト。4小節（ドラム56音・ほか23音、2つめのクリップ、16分の音）が、再生で全部・正しい時間に鳴るか、4小節で頭にもどって同じだけ鳴るか（音を鳴らす関数を数える）
